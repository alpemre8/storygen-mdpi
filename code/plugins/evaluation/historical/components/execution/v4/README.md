# Locked owner execution v4

One owner invokes its exact DAG using one global run ID and one canonical owner-depot run directory. Provider stages write only below that root, in provider work directories, and record their source identities. There is one run manifest/seal; companion repos do not create competing owner runs. Artifact registry v2 preserves v1 read compatibility. Scientific algorithms stay in exact historical providers or frozen reviewer API bundles; old technical versions remain available.

Source providers are detached local Git worktrees with full tracked-file hashes; untracked content that could shadow code is rejected (interpreter/test caches excepted). Normal subprocess imports replace mutable sys.path edits in new code. No network resolution is performed. The lock pins Python and its runtime dependency closure, exact source commits/trees/components/assets, model checkpoint SHA, profile identity and backend executable/shared-library bytes. Absolute installations are operational bindings; moving an installation requires an explicit hash-preserving lock/config update, never an automatic model/version substitution.

The original lock bytes and owner code receipt are frozen into the run. Each immutable DAG job hashes argv, configuration, lock and upstream job IDs. Each stage records the actual upstream artifact refs/hashes, verifies them before execution, emits started/terminal receipts, and prints elapsed/ETA HH:MM:SS. Provider-specific frozen output schemas and calibration gates remain enforced by the original scientific code. Technical execution success cannot establish semantic validity of LLM output.

The owner runner supports plan/doctor/preflight/run/status. Configless discovery reports HUMAN_OR_RUNTIME_BLOCKED and required bindings. Doctor checks package/source/input/model/backend hashes, profile context/slots and free local ports, plus fresh writable roots; PLAN_READY means preflight only. RUNNING identifies the exact live owner PID/start ticks/boot ID. Interrupted RUN_STARTED roots are incomplete/blocked. PASS means COMPLETE execution with scientific validity still UNVERIFIED. Failures stop downstream work and retain partial output/receipts; an integrity mismatch is retained as FAILED/INVALID with explicit evidence. New attempts require fresh IDs and parent links.

The three end-to-end offline fixtures reuse the actual TasksetV5, E02 and E03 owner DAG shapes and exact locked providers; subprocess stubs emit synthetic identity records only. They make zero HTTP inference calls and verify one physical root, one global ID, provider artifact authority, hashes, exact lock bytes and all required stages. Live TasksetV5 and E-series verification belongs to M11.
